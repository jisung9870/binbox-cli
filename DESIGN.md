## Brand

- Personality: calm, capable, compact, and safe; a tool for one frequent operator rather than a generic dashboard.
- Trust signals: explicit selected row, visible result count, stable key hints, clear cancel behavior, and no hidden mutation.
- Avoid: copying fzf's layout for familiarity alone, decorative noise, Nerd Font requirements, nested full-viewport boxes, excessive borders, and color-only state communication.

## Product goals

- Goals: make search and completion immediately discoverable, make common selection possible without mode knowledge, preserve fast keyboard operation, present polished human-readable output by default, retain explicit stable JSON for automation, make frequent secret use possible without printing plaintext into the parent shell, let an operator follow read-only AWS resource relationships without changing console pages, and let the AWS browser change profile/account/region without restarting the command.
- Non-goals: pixel compatibility with fzf or k9s, mouse-first operation, a general TUI framework, Git workflow expansion, AWS resource mutation, replacing exact live resource reads with a stale snapshot, a continuously running cloud dashboard, or previews that can expose secrets. A Terraform plan is read through the plan's own sensitivity markers, so plan review is a reading surface rather than an exception to that last rule.
- Success signals: Tab completes supported commands/options and safe local metadata; default structured reads render labels/tables rather than JSON; `--json` preserves schema-v1 envelopes; typing any printable character immediately filters; the first arrow press moves selection; Enter selects; Escape clears the query before navigating back or cancelling; secret management exposes only service/field metadata; service selection scopes the field list; rename, destructive, or overwrite actions default to Cancel; scoped execution passes values only to the child process; stderr-only rendering and stable-value output remain unchanged.

## Personas and jobs

- Primary personas: the repository owner using bb repeatedly from zsh, tmux, Terminal.app, iTerm2, or an Orca terminal.
- User jobs: locate one project/profile/environment/item quickly, distinguish similar names, confirm the target, and return to the invoking command without residual terminal output.
- Key contexts of use: lists from a handful to hundreds of entries, narrow terminal panes, repeated daily use, and security-sensitive profile or secret labels.

## Information architecture

- Primary navigation: one search field, one ranked result list, and one persistent compact key-hint footer. AWS browse is a full-terminal workspace with a fixed context/header area, a k9s-style dense column table, and a fixed command/help footer. Home, configured-profile, resource, Overview, relation, and Tags selection screens all use a visible column header; Detail remains a scrollable key/value document viewer. AWS configured-profile and resource lists use the same always-visible local filter pattern; filtering never dispatches an AWS request. `:` opens a k9s-style resource command line, while direct typing and `/` both enter local filtering.
- Core routes/screens: one reusable selector surface, a secret Service selector followed by a Field selector and safe Action selector, an AWS Profile Context→Service→Resource→Overview→Detail/Relation/Tags→Linked Resource browser, one reusable default-cancel confirmation card, zsh completion states, and one generic human output hierarchy for bb-owned structured results. `bb aws browse` without `--profile` starts at Profile Context; an explicit `--profile` starts at Home. Home exposes EC2, Route 53, IAM, VPC, and a regional `Load Balancers (ALB/NLB)` catalog; `:elbv2`, `:alb`, and `:nlb` open the combined or type-filtered catalog directly. Security Group and VPC Overview add an `Incoming relations · AUTO` category; entering it is the explicit trigger for bounded Context Group collection and does not require a preceding `bb aws sync` command.
- Content hierarchy: command-specific staged navigation keeps broad lists first and full details last. Secret management uses Service→Field→Action; AWS browsing uses Service→Resource→Overview, with optional Category content→Linked resource depth only when more evidence is needed. Opening a resource lands on a service-aware Overview: up to eight recognized identity, state, network, or service fields appear under `At a glance`, and every relation or Tags category includes up to two human-label-first values in a `PREVIEW` column at 72 columns or wider. The preview is local projection data and never dispatches another AWS request. Detail opens the complete projected field set only when requested. Narrow screens omit `At a glance` before hiding selectable Explore rows. An exact linked-resource read that completes with one resource skips the generic `Resources (1)` result screen and opens Overview directly; true collections retain their resource list. A Route 53 alias Overview adds `Target trace`: one Enter performs a bounded breadth-first live read across Alias→ALB/NLB or CloudFront→Listener/Rule→Target Group/Origin→registered target and displays every observed node in one indented resource list. The manual Alias target category remains for evidence-first inspection. Security Group Overview provides direct Inbound rules and Outbound rules categories. IAM Role Overview provides Attached policies and Inline policies previews; opening a policy hydrates exact metadata, and a managed policy exposes its default Policy document. Route 53 Hosted Zone Overview previews DNS records. Load Balancer rows distinguish ALB/NLB in the TYPE column; ALB listeners expose ordered Listener rules and default Target groups, while NLB listeners expose only their default Target groups. Both continue through registered targets. A Route 53 record whose API-exact Alias target is the fixed AWS CloudFront alias zone can trace the matching same-account CloudFront distribution and inferred S3 origins; its Origins category retains each cache behavior's path pattern, including the default route. Unsupported or unowned DNS targets remain evidence-only, preserve the raw target reference, and open Relationship evidence with Enter/→ or `e` instead of appearing unresponsive. Policy documents and Route 53 routing/alias structures render as readable multi-line JSON in Detail. Tags opens a local key/value list and never dispatches AWS work.

## Design principles

- Search is the default action: printable input filters immediately; `/` remains an optional shortcut, not required knowledge.
- Full screen is working space: AWS browse uses the available terminal rather than centering a bounded card; additional width and height increase visible columns, relationship evidence, and table rows.
- Tables carry the operational context: resource rows prioritize `NAME`, `TYPE`, `ID`, `STATUS`, then account/region; relation rows prioritize `DIR`, `RELATION`, `TARGET`, `CONDITION`, then confidence/scope. A selected row is one full-width highlight and never repeats an `enter open` action in every row because the footer owns key hints.
- k9s conventions are additive: `:` provides resource aliases and actions, `/` explicitly focuses filtering, and `Ctrl-o`/`Ctrl-i` move through browser history without removing the existing arrow-key contract.
- One key, one visible effect: arrows move on the first press, Enter selects on the first press, and Escape has a predictable clear-then-cancel sequence.
- No singleton list detours: an exact relation lookup that yields one resource replaces its transient result frame with Overview, so Left returns to the relation/category screen; list screens remain for zero, partial, or multiple results.
- Context without clutter: show one muted metadata line only when it helps distinguish choices.
- Human label first: any projected AWS resource with a non-blank `Name` tag uses it as the primary row/detail title and keeps its stable resource ID as secondary identity. If the tag is absent, use the resource's native name field (for example a Security Group group name); if neither exists, use the ID as the title. Tags never remain as an inline JSON/detail field.
- Verified AWS context: profile owns credentials, account/principal are derived only from STS identity, and region is explicit. Changing account therefore means choosing a profile that verifies to that account; raw account IDs are never accepted as an authentication selector.
- Conditional relationships stay conditional: CloudFront cache-behavior path patterns are edge labels, never flattened into one unconditional distribution-to-origin link. Duplicate buckets remain separate rows when different paths select them.
- Human first, machine explicit: bb-owned structured reads render concise labels or tables by default and use `--json` for the stable schema envelope.
- Scoped secret navigation: enter a service before choosing one of its fields; show field counts on services and keep field rows flat and compact.
- Safety survives styling: UI stays on stderr, selected stable values stay on stdout, and sensitive values never become preview metadata.
- Secret actions are staged: selection never performs a mutation; copy is the default safe action, replacement confirms before hidden entry, and rename/removal confirm before writing. Rename moves the existing in-memory value to a validated unused field name and never displays it.
- Tradeoffs: direct typing gives up unmodified `j`/`k` navigation while the query is active; arrows and `ctrl+n`/`ctrl+p` remain unambiguous navigation keys.

## Visual language

- Color: adaptive light/dark terminal colors with a confident violet primary, cyan navigation/search accents, green ready states, amber read-only/loading states, red failures, a visible selected-row background, muted metadata, and a monochrome `NO_COLOR` path. Color reinforces but never replaces the `>`, `!`, status text, or labels.
- Typography: terminal-native text only; no icon font dependency. Use simple glyphs such as `>` and `•` with ASCII fallbacks where needed.
- Spacing/layout rhythm: one-line header, one-line context/breadcrumb row, one-line search/status row, one uppercase column-header row, a dense table that expands to consume remaining height, and a fixed one-line footer. AWS browse always uses the full terminal; compact terminals reduce rightmost secondary columns before reducing the selectable table. Table cells use two-space gutters and no vertical separators.
- Shape/radius/elevation: a single restrained perimeter border may frame the AWS workspace; no centered card, nested boxes, or simulated shadows.
- Motion: cursor blink only; no animated loading or decorative transitions in the selector.
- Imagery/iconography: none.

## Components

- Existing components to reuse: Bubble Tea program lifecycle, Bubbles fuzzy filter/ranking, Bubbles text input/list behavior where it matches the interaction contract, and Lip Gloss styles already supplied transitively.
- New/changed components: a bb-owned selector view, always-visible search row, result counter, explicit empty state, compact help footer, command-specific optional detail/keywords, a default-cancel confirmation card, a staged selector that holds a stack of levels inside one program, a three-stage Service/Field/Action secret manager built on it, an AWS context selector with a locally filtered configured-profile table, editable region, derived verified account/principal, and apply/cancel states, locally filtered AWS resource tables, a service-aware Overview with inline category previews, local relation edge tables, a local searchable Tags table, a k9s-style AWS command line with resource aliases, backward/forward browser history, an optional snapshot-backed read-only AWS relationship graph beside the current live progressive browser, native zsh completion, and a generic control-safe human renderer.
- Staged selection: a multi-level walk is one program, not one program per level. Entering a value pushes the next level and Escape pops back to the previous one with its query and cursor intact, so the alternate screen is entered once and returning to a level does not discard the search that got you there. Each level is an ordinary selector; the level graph is supplied by the command as a function from the values chosen so far to the next level. Levels with no choices complete the walk rather than rendering an empty list.
- Variants and states: service browsing, field browsing, AWS resource/relationship browsing, exact/heuristic links, partial AWS permission failure, searching, filtered, completion with/without dynamic candidates, human detail/table/empty output, JSON envelope, no results, empty source, action selection, rename input/confirmation, overwrite confirmation, removal confirmation, plan resource list, plan attribute reading, redacted and not-yet-known values, narrow terminal, no-color, and numbered fallback.
- Reading versus choosing: a level can be marked read-only, which drops Enter and the select hint from its footer. A viewer must not be closable by the same key that opened it, and a walk never completes on such a level.
- Token/component ownership: selector styles and keymap live beside `internal/bb/select.go`; do not introduce a repository-wide design-system package.

## Accessibility

- Target standard: keyboard-complete operation, readable contrast, no required color perception, and stable text labels.
- Keyboard/focus behavior: Tab completes commands/options and safe candidates through native zsh completion; printable keys search; arrows or `ctrl+n`/`ctrl+p` move; PageUp/PageDown page; Home/End jump; Enter selects; Backspace edits; Escape clears query, then returns Action→Field→Service, then exits from Service; Ctrl+C always exits the manager. In AWS browse, Up/Down move the cursor, Right and Enter open the selected service/resource/category/relation, and Left returns exactly one browser screen without first clearing a local filter. `:` opens a command line accepting documented resource aliases and actions; `/` focuses the current local filter; `Ctrl-o` moves back and `Ctrl-i` moves forward through completed browser frames. Printable input still locally filters a resource list without requiring `/`. `c` opens context selection while the resource query is empty. In context selection, printable input locally filters profiles, arrows choose a filtered profile, Tab moves to the editable region, the first Enter verifies account/principal, and the second Enter applies. Escape clears the active local query first; on the initial profile gate it then continues to ambient Home, while an in-browser context change returns to the previously active view. In resource Overview, Up/Down selects a visible relation, Detail, or Tags category; Right or Enter opens it. Related-resource lists use Up/Down and Right/Enter, while full Detail uses Up/Down or PageUp/PageDown to scroll. Left returns one screen at a time.
- Contrast/readability: selected state uses both a marker and style; matched characters use emphasis in addition to color; metadata remains readable on light and dark terminals.
- Screen-reader semantics: retain the numbered plain selector as the deterministic accessible fallback through `BB_SELECTOR=plain`.
- Reduced motion and sensory considerations: honor `NO_COLOR`; avoid animation and rapid redraw outside input changes.

## Responsive behavior

- Supported breakpoints/devices: character terminals from 24x8 upward; optimize for 40-120 columns and 10-40 rows.
- Layout adaptations: AWS browse fills the available viewport at every supported size. Resource tables show `NAME·TYPE·ID` first, then `STATUS·ACCOUNT·REGION`; relation tables show `DIR·RELATION·TARGET·CONDITION` first, then `CONFIDENCE·SCOPE`. Wider terminals reveal the rightmost columns and taller terminals reveal additional rows. Below 60 columns, keep a reduced header rather than reverting to prose rows. Below 50 columns or 14 rows, compact whitespace and preserve search/selection/footer before secondary metadata; never force an 80x20 visual canvas into a smaller pane.
- Touch/hover differences: not applicable; mouse support is deferred.

## Interaction states

- Loading: with explicit `--profile`, AWS Home remains the first local-only screen. Without `--profile`, configured-profile discovery is the first screen and remains a bounded local-only operation; the loading card appears immediately and typing later filters only the loaded choices. Applying a profile/region performs one cancellable credential/STS identity resolution and no resource read. Resource routes remain progressive; typing filters the current projection locally and performs no network work per keystroke. Entering `Incoming relations` starts one cancellable automatic graph collection only when the active snapshot is older than five minutes or lacks successful coverage for a configured profile×region scope. `Ctrl+R` forces recollection; Escape cancels without replacing the previous complete snapshot.
- Empty: explain that the source has no selectable items and exit without entering an unusable selector. A non-empty local query with no matches stays on the current AWS screen and says `No matches for “query”` so Backspace or Escape can recover immediately.
- Error: return to the caller with the existing typed error; do not leave alternate-screen artifacts. AWS context discovery or verification failure stays on the selector, shows a sanitized typed state, and preserves the previously active context. A failed linked-resource exact read with no result collapses back to the parent Overview and reports typed state, service, operation, and safe error code there. Target trace keeps its root alias and any successfully observed nodes visible when one branch is denied or fails.
- Success: immediately close and return exactly one stable value per level. A staged walk closes once, after the last level, and returns the chosen values in order; mutations still run after the selector has closed. Successful AWS context apply returns Home, clears resource navigation history, and updates the visible verified profile/account/principal/region before another resource read.
- Disabled: unavailable actions are omitted from the footer rather than shown as inactive decoration.
- Offline/slow network, if applicable: provider fetching remains outside the selector; the selector itself performs no network work. Partial AWS service failures remain visible as warnings, while total failure points to SSO/profile and read-only permissions.

## Content voice

- Tone: short, direct, and action-oriented.
- Terminology: use `Search`, `results`, `select`, `clear`, and `cancel` consistently; use the command domain in the title such as `Select AWS profile`.
- Microcopy rules: show keys beside verbs (`↑↓ move`, `enter select`, `esc clear/back`); use `No matches for “query”` rather than an empty list. AWS list search rows use `Search  query` and show filtered/total counts. The AWS context screen says `Account follows verified profile credentials` and never suggests that an account ID alone can be selected or authenticated.

## Implementation constraints

- Framework/styling system: Go with Bubble Tea, Bubbles, and Lip Gloss; no external `fzf` or `k9s` process and no new dependency for the full-screen/command-line redesign.
- Design-token constraints: adaptive ANSI colors, `NO_COLOR`, and terminal width-aware truncation; preserve labels and stable values separately.
- Performance constraints: filtering and rendering 250 items must remain perceptually immediate and must not start provider or filesystem work per keystroke. Repeated AWS snapshot collection above 10 seconds is the trigger for lazy loading and cache design. One Target trace is bounded to 64 exact read queries and 500 projected resources, deduplicates query targets, remains cancellable, and reports `trace_limit` instead of silently truncating.
- Compatibility constraints: `bb setup shell` idempotently registers `eval "$(bb shell init zsh)"`, which remains the only required `.zshrc` line and provides completion without checkout paths; dynamic candidates use local names/IDs only and never values or credentials; all TUI writes go to stderr; `--json` preserves the schema-v1 envelope; non-TTY, dumb terminal, and `BB_SELECTOR=plain` behavior remain deterministic, including a numbered context selection path; `sec exec` replaces only the selected service's normalized environment keys in the child and never mutates the parent environment; AWS CLI remains the credential/profile/page owner and `bb aws browse` calls read operations only. Context discovery may read configured profile names and their non-secret region values; account/principal appears only after STS verification.
- Test/screenshot expectations: generated zsh syntax/registration smoke, candidate non-disclosure tests, human-vs-JSON output regressions, AWS fixture tests for exact argv/relations/partial failure, model-level key sequence tests, width/height snapshots or golden text with color disabled, PTY smoke in direct zsh and tmux, and regressions for stdout cleanliness and alternate-screen cleanup. Staged selection additionally requires model-level tests that no level transition returns a quit command, that Escape clears then pops then cancels, that a level keeps its query and cursor when returned to, that a resize reaches levels that are not currently visible, and that the plain walk pops on an empty answer.

## AWS multi-region context decision

- Profiles remain the account and permission boundary. A context group adds only a named set of profiles and regions; it never stores credentials, account IDs, or principals.
- The context selector exposes profile, current region, and regional scope as separate controls. `Current region` is the default. `All <group> regions` is available only when the selected profile belongs to a group with at least two configured regions.
- Regional catalog routes such as EC2 and VPC fan out across the selected group regions and merge progressive results. IAM, Route 53, and CloudFront remain single global queries. Exact linked resources, including S3 bucket-region lookup, always use the resource's observed region and do not fan out.
- Multi-region projections retain the verified context on every resource. Selecting a resource therefore locks subsequent detail and relationship queries to the exact profile and region that produced it.
- Context groups are read from `$XDG_CONFIG_HOME/bb/aws-contexts.json`, falling back to the OS user-config directory (`~/.config/bb` on WSL/Linux). The file is strict, bounded JSON and contains only group names, configured profile names, region names, and defaults. Missing configuration preserves the existing single-region selector.
- Region fan-out is bounded and current-region-first. Partial failures keep successful regional results visible and expose per-region coverage instead of collapsing the whole view into one failure.

## AWS live and snapshot graph decision

- Live Browse remains the default source for Service→Resource→Overview→Detail and exact linked-resource verification. It continues to use the existing AWS SDK providers and in-memory session store.
- B4-A wires the versioned SQLite snapshot store to `bb aws sync sg` and `bb aws refs sg`. B4-B1 adds `bb aws sync graph` and `bb aws refs vpc` for exact VPC Peering participant edges without replacing the active run with a separate network-only snapshot. B4-C exposes the same store in Security Group and VPC Overview through `Incoming relations · AUTO`: a fresh, fully covered five-minute snapshot is reused; otherwise Browse invokes the Go sync/read services in-process for the selected Context Group. `bb aws sync` remains an advanced prewarm/automation command, not a normal Browse prerequisite. Unsearched participant accounts remain explicit `not-observed` coverage. TGW, PrivateLink, `whois`, and `diff` remain later B4 work. The store contains normalized resource identity, observation, relation, and succeeded/failed/not-observed coverage, but no credentials or unbounded provider `raw_json` payloads.
- Snapshot-backed screens must always show snapshot age plus successful, failed, and not-observed account/region coverage. A graph result is never presented as live data.
- Opening a snapshot node uses the edge observer profile and region as an unverified hint, resolves that context through STS, and transitions to an exact live read only when partition/account/profile/region match the stored observer identity. Same-context rows reuse the already verified context. Identity mismatch, login-required, denied, or cancellation keeps the snapshot list unchanged; `e` opens the stored evidence without attempting live access. EC2 instance, SG/rule, and VPC Peering incoming rows have narrowed exact-read resolvers.
- Both paths share canonical `ResourceKey`, relationship confidence/evidence, provider normalization, and a Go query service. The TUI never shells out to a bb CLI command to obtain its own data.
- `modernc.org/sqlite v1.57.0` is accepted for the optional snapshot store after the B3 100k-resource/500k-relation PoC, atomic-run, retention, and corruption-recovery tests. It is a lazy relationship cache and is not a prerequisite for Home or live forward navigation. See `aws-plan/B3-SNAPSHOT-GRAPH-POC.md`, `aws-plan/ADR-002-SQLITE-SNAPSHOT-GRAPH.md`, `aws-plan/B4A-SG-SNAPSHOT-REFS.md`, `aws-plan/B4B1-VPC-PEERING.md`, and `aws-plan/B4C-AUTO-INCOMING-RELATIONS.md`.
